# The engine now emits what production loads

`AmunEV/evidence/sample_bundle/` is a real bundle, generated by the engine's own
`laz_deploy` over the 142 strategies in `books/MODE3_202748.xlsx`.

## What was wrong

The engine and the live stack did not agree on a single field. Measured against
the production sources, the bundle the engine wrote before this change could not
have loaded at all:

| field | the engine wrote | production requires | what happens |
|---|---|---|---|
| `conditions` | `{'term': 'prog_score', 'op': '<=', 'value': '0.35'}` — a dict, 683 of 683 | a `text[]` of single clauses matching `_COND` | `unparseable condition` → the sport loads **zero** strategies |
| `market` | `None` (270 of 270), else `totals` / `moneyline` / `total_goals_handicap` | one of the sport's `SETTLEABLE_MARKETS` | `market not settleable here` → the sport loads **zero** strategies |
| `bet_role` | `prop:late_lead_hold`, `spec:Leader`, `tg_under`, `q1_winner` … | one of 12 roles `resolve_side` answers | **no error** — `resolve_side` returns None and the strategy never fires again |
| thresholds | `repr(float)` → `1e-05`, `-inf` | `-?\d+(?:\.\d+)?` only | `unparseable condition` → the sport loads **zero** strategies |
| feature columns | names up to 75 bytes | Postgres identifiers ≤ 63 bytes | the ALTER truncates with a notice, `feature_columns()` then raises `namespace names columns absent` and the sport will not start |
| PCA composites | `pc_<hash>` with a manifest a worker could overwrite | a computable number | every strategy conditioning on one was excluded |

Four of those six raise nothing. A registry that loads cleanly is not the same
thing as a registry that bets what the engine measured.

## What the engine emits now

At the moment `laz_xl__write` writes the book — same `A`, same run — it writes
`production/<sport>/`:

- **`deploy.sql`** — one idempotent transaction: the `rt_allsports_laz_features`
  columns, then `laz_feature_namespace`, then `laz_strategy_registry`, then
  `laz_strategy_provenance`, in exactly the order the loader reads them. Anything
  this run did not re-validate is disabled, so the live book is this run's book.
- **`laz_pca_features_<sport>.py`** — the run's frozen PCA transforms as importable
  production code. Verified to reproduce numpy's `float32` **bit for bit**; a tick
  with any input missing or non-finite yields `None`, never `0`.
- **`verify_live.py`** — reads the database back and re-applies every gate.
- **`quarantine.csv` / `.json`** — every validated strategy that is *not* shippable
  unchanged, with the exact production error it would have caused and its full
  acceptance record. None of them is in `deploy.sql`: one bad row takes the whole
  sport down at load.
- **`MANIFEST.json`**, **`RUNBOOK.md`** — the machine-readable bundle and the
  operator page, including a ranked list of which features to build to recover the
  withheld strategies.

## The gates

Each is transcribed from the production source, and the test suite re-derives every
one of them from those files rather than from a restatement here.

| # | rule | production's response when violated |
|---|---|---|
| G1 | every clause matches `_COND` | `unparseable condition` — sport loads zero |
| G2 | every threshold is a plain decimal | same |
| G3 | at least one row survives | `ZERO enabled <sport> strategies` |
| G4 | market ∈ `SETTLEABLE_MARKETS` | `market not settleable here` — sport loads zero |
| G5 | every term has a namespace row | `has no namespace row` — sport loads zero |
| G6 | every namespace column exists | `namespace names columns absent` — will not start |
| G7 | `bet_role` ∈ what `resolve_side` answers | **silence** — never fires again |
| G9 | the band is finite and ordered | **silence** — a NaN bound admits every price |
| G10 | at least one condition survives | **silence** — fires on every match |
| G11 | column names ≤ 63 bytes and unique | Postgres truncates with a notice |
| G12 | the shipping text rebuilds the measured bets | **silence** — bets the search never measured |
| G13 | every `pc_*` has its frozen transform | **silence** — the composite is None forever |
| G14 | production computes every condition term | **silence** — the condition answers None forever |

## Nothing the search validated is thrown away

Two of the gates above were mine, not production's, and they are gone:

- **A term production does not yet compute is the engine's job.** `laz_featuregen__write`
  emits that term's implementation 1:1 from the engine's own builder, and
  `laz_featuregen__prove` replays the frame through the generated file and diffs every
  value against the pool the search used, exact to float32. So the bundle **ships the
  feature** (`laz_features_<sport>.py`) with the strategy instead of refusing it.
- **A base that arms on more than a role is not missing information.** `late_lead_hold`
  is `_lead(C, 0.85, 1.2, 3)` — the leader, in the last 15%, 4+ up. The engine knows that
  exactly, so the window is **emitted as conditions** (`u_elapsed >= 0.85`,
  `u_elapsed <= 1.2`, `abs_lead > 3`) and stacked in front of the strategy's own. The
  registry's condition list IS the execution order.

What remains withheld is production's own limit, not a judgement: a market its evaluator
cannot settle (a point spread, a quarter or half result). Those are **still written to
`laz_strategy_registry`, with `enabled = false` and `blocked_reason`** — in the database,
joinable to their provenance, unable to fire and unable to break the load.

## Every element, in the exact order it happens

`element_doc` (schema `amunev.element_doc/2`) now carries the ordered implementation,
written at acceptance inside the search worker. For `late_lead_hold` with two conditions:

| # | gate | must be true | if not |
|---|---|---|---|
| 1 | MARKET OPEN | `market_status == 'Open'` | skip this tick entirely |
| 2 | FEED FRESH | `tick_gap_s is null OR tick_gap_s <= 180` | skip this tick entirely |
| 3 | BASE ARM MASK — SIDE | `resolve_side('leader') is not null` | do not fire; never guess a side |
| 4 | BASE ARM MASK — WINDOW 1 | `u_elapsed >= 0.85` | do not fire on this tick |
| 5 | BASE ARM MASK — WINDOW 2 | `u_elapsed <= 1.2` | do not fire on this tick |
| 6 | BASE ARM MASK — WINDOW 3 | `abs_lead > 3.0` | do not fire on this tick |
| 7 | PRICE OF THE BACKED SIDE | `price = price_for_side(side); price == price` | do not fire; a NaN price passes every bound |
| 8 | PRICE BAND | `1.4 <= price <= 4.2` | do not fire on this tick |
| 9 | CONDITION 1 | `line_move <= 4.0` | do not fire (a null fails closed) |
| 10 | CONDITION 2 | `trailer_price >= 1.92` | do not fire (a null fails closed) |
| 11 | FIRST TICK ONLY | this (match_id, strategy) has not fired before | do not fire again in this match |
| 12 | PLACE | back `leader` at price, market `match_winner` | — |
| 13 | SETTLE | the backed side wins the match | unsettled is excluded, never a loss |

Read top to bottom, stopping at the first step that is not true, this **is** the
implementation. `STRATEGY_SPEC.md` carries one of these per strategy;
`strategies_full.json` carries the same machine-readable.

`spec_sha` now covers the base mask, so two strategies with identical conditions and
different masks are no longer hashed as the same strategy. `exec_sha` hashes the ordered
steps themselves.

## The result on the real book

**128 of 142 live**, preflight PASS, 14 registered-not-live (all of them markets the
basketball evaluator cannot settle). Before any of this work, the number that could load
was **0**.
